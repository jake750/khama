# الأمان: سياسة المحتوى (CSP) وحدود الواجهة

## سياسة المحتوى في `tauri.conf.json`

| التوجيه | القيمة | السبب |
|---|---|---|
| `default-src` | `'self' ipc: http://ipc.localhost` | الواجهة لا تحمّل إلا ملفاتها، وتكلّم Rust عبر قناة Tauri فقط. |
| `script-src` | (يرث `default-src`) | لا سكربت من أي نطاق خارجي ولا `eval`. |
| `img-src` | `'self' https: data:` | صور معاينة الرابط تأتي من خوادم كل موقع (i.ytimg.com، scontent.cdninstagram.com، pbs.twimg.com، …) ولا قائمة ثابتة لها: yt-dlp يدعم أكثر من ألف موقع. `data:` للصور المصغّرة التي يولّدها FFmpeg في المحوّل. |
| `media-src` | `'self' https: blob:` | معاينة القص تشغّل رابط الفيديو المباشر الذي يعطيه yt-dlp، وهو على خوادم الموقع نفسه (googlevideo.com وغيرها) وتتغيّر نطاقاتها. |
| `style-src` | `'self' 'unsafe-inline'` | React يكتب `style` لقيم محسوبة (عرض شريط التقدّم، موضع المؤشر). |
| `font-src` | `'self' data:` | الخط مضمّن في التطبيق. |
| `connect-src` | `'self' ipc: http://ipc.localhost https://api.github.com` | فحص آخر إصدار لـ yt-dlp من GitHub. كل تنزيل آخر يمرّ عبر Rust لا عبر `fetch` في الواجهة. |

### لماذا `https:` واسعة للصور والفيديو فقط (T-60)

الصور والفيديو لا تنفّذ كودًا، فأسوأ ما يحدث لو حُقن رابط صورة هو طلب GET إلى نطاق ما. حصرها بقائمة نطاقات يكسر المعاينة مع كل موقع جديد أو تغيير في شبكة توزيع المحتوى، بلا مكسب أمني يُذكر. أما ما ينفّذ كودًا أو يرسل بيانات (`script-src`، `connect-src`) فمحصور بالتطبيق نفسه وبنطاق واحد معروف.

## حدود أخرى في Rust

- `reveal_file` لا يفتح إلا ملفات أنتجتها خامة في الجلسة أو ملفات في السجلّ (T-33)، فلا تستطيع الواجهة لو حُقن فيها كود أن تفتح أي مسار على الجهاز.
- الروابط تُفحص في `validate_url` (http/https فقط) قبل أن تصل إلى yt-dlp.
- الأدوات (yt-dlp، FFmpeg، Deno) ونموذج فصل الصوت تُفحص ببصمة SHA-256، والنموذج يُعاد فحصه عند أول استعمال في كل تشغيل (T-102).
