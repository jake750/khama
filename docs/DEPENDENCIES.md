# الاعتماديات الكبيرة ولماذا اخترناها

قيست الأحجام في 2026-11-17 على Windows x64.

## Deno لتشغيل JavaScript يوتيوب (T-91)

| الأداة | الحجم |
|---|---|
| Deno 2.9.8 | 98 MB |
| yt-dlp | 24 MB |
| FFmpeg (مع المكتبات) | 186 MB |

**لماذا:** يوتيوب يحمي روابط الفيديو بكود JavaScript يتغيّر كل بضعة أسابيع، وyt-dlp يحتاج محرّك JavaScript حقيقيًا لحلّه (`--js-runtimes`). بدونه تفشل أغلب تنزيلات يوتيوب أو تنزل بجودة منخفضة.

**البدائل التي قارنّاها:**

| البديل | الحجم | لماذا لم نختره |
|---|---|---|
| Node.js | ~80 MB | قريب من حجم Deno، ودعم yt-dlp له أحدث وأقل اختبارًا. |
| QuickJS | ~1 MB | yt-dlp يدعمه، لكن توثيقه يصفه بأنه أبطأ بوضوح في حل الحماية. نستعمله على الهاتف فقط حيث لا بديل. |
| JavaScript داخل WebView التطبيق | 0 | لا واجهة في yt-dlp لاستدعائه، ويحتاج تعديل yt-dlp نفسه. |
| بلا محرّك | 0 | يوتيوب أهم مصدر للمستخدمين، وفشله يُسقط فكرة التطبيق. |

Deno هو المحرّك الذي يوصي به yt-dlp ويختبره أولًا، لذلك اخترناه رغم حجمه. على الهاتف لا يوجد Deno: yt-dlp يعمل عبر Python المضمّن مع QuickJS.

## ort (ONNX Runtime) نسخة مرشّحة (T-38)

`ort = "=2.0.0-rc.10"` مثبّتة على نسخة rc بعلامة `=`. لا توجد نسخة 2.0 مستقرة حتى اليوم (آخرها `2.0.0-rc.15`)، وسلسلة 1.x قديمة وواجهتها مختلفة كليًا.

- التثبيت بـ `=` مقصود: نسخ rc تكسر الواجهة بينها، فلا يرقّي `cargo update` إلى نسخة لم تُختبر.
- المكتبة الأصلية (`onnxruntime` 1.22) تُنزَّل من إصدارات Microsoft الرسمية بنسخة ثابتة وبصمة SHA-256.
- الترقية: حين تصدر 2.0 مستقرة، نرقّي `ort` والمكتبة معًا ونشغّل اختبار الفصل الحقيقي.

## مصدر نموذج فصل الصوت (T-39)

النموذج `UVR-MDX-NET-Voc_FT.onnx` (67 MB) من مستودع `TRvlvr/model_repo`، وهو مستودع طرف ثالث قد يُحذف. لذلك في `separate.rs` نسختان احتياطيتان على Hugging Face (`MODEL_MIRRORS`) تُجرَّبان بالترتيب إن فشل الأصل.

- كل نسخة تُفحص بالبصمة نفسها، فنسخة معدّلة تُرفض كما يُرفض الأصل.
- Hugging Face يعلن بصمة SHA-256 للملف في ترويسة `X-Linked-ETag`، وطابقت البصمة المحفوظة عند الإضافة.
- رفع النموذج إلى إصدارات مشروع خامة نفسه أضمن، لكنه توزيع للنموذج، فيتبع قرار رخصة النموذج (من البنود التي يقرّرها صاحب المشروع).
